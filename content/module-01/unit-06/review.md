# Review and mastery check

This is **self-assessed**. Nobody else checks it. Be honest; it is for you.

## Review checklist

Tick only what is true.

- [ ] `m1-p6` passes in the checker.
- [ ] I typed the commands myself. I did not paste them (except the debugging lab's setup).
- [ ] I followed my own README in a fresh clone.
- [ ] `verify.sh` fails when I break lint on purpose.
- [ ] The school's name is typed once. Nothing private is tracked.
- [ ] In the debugging lab I wrote the cause before I changed anything.

## Compare with GPIS

Write three to five sentences on the platform:

- Read GPIS's `README.md` and `AGENTS.md`. Name two rules there that you did not think of, and
  say what accident each one prevents.
- Open `src/config/school.ts` in GPIS. What is in it besides the name? Why does a printed
  report card make this module important?
- GPIS says to run lint, build and a type check before saying "it works". Which of the three
  can your project run today?

## Mastery check

Close the lesson. Do each task, then test yourself by running the commands.

1. From an empty folder, in 30 minutes: repository, ignore file, `package.json`, one module,
   one script that imports it, lint, verify script, README.
2. Explain why `;` and `&&` differ, with a two-line example you run.
3. Say what would go wrong, step by step, if `.env` were committed and pushed.
4. Explain your `RULES.md` to someone as if they were joining the project.

**You have mastered this unit when** you did all four without help. If not, redo the guided
example tomorrow, not today, and try again.
